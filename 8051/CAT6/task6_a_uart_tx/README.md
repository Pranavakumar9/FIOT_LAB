### Circuit Functionality
- **Cross-Wiring:** The AT89S52 TXD line (P3.1, Pin 11) is wired to the USB-to-TTL adapter's RXD pin. Transmitted bytes are converted from parallel byte format into standard asynchronous NRZ (Non-Return-to-Zero) serial stream and transferred over the USB bus to the host operating system's virtual COM port.
- **Common Ground:** Sharing a direct, low-inductance ground return between Pin 20 and the adapter ground is mandatory to maintain signal integrity and avoid framing errors.

## 7. Theory and Baud Rate Derivation

### 1. 8051 UART Mode 1 Principles
- 10-bit frame structure: 1 Start bit (`0`), 8 Data bits (LSB first), 1 Stop bit (`1`), no parity.
- Serial Control Register (`SCON`):
  - `SM0 = 0`, `SM1 = 1` $\implies$ Mode 1 (8-bit UART, variable baud rate generated by Timer 1).
  - `REN = 1` $\implies$ Receiver enabled.
  - Value: `0b01010000 = 0x50`.

### 2. Baud Rate Equation
The baud rate in UART Mode 1 with Timer 1 in Mode 2 (8-bit auto-reload) is given by:
$$\text{Baud Rate} = \frac{2^{\text{SMOD}}}{32} \times \frac{F_{\text{osc}}}{12 \times (256 - \text{TH1})}$$
Setting $\text{SMOD} = 0$ (Bit 7 of `PCON`), $F_{\text{osc}} = 11.0592\text{ MHz}$, and desired $\text{Baud Rate} = 9600$:
$$9600 = \frac{1}{32} \times \frac{11,059,200}{12 \times (256 - \text{TH1})} = \frac{28,800}{256 - \text{TH1}}$$
$$256 - \text{TH1} = \frac{28,800}{9600} = 3$$
$$\mathbf{TH1 = 256 - 3 = 253 = 0xFD}$$
Because $28,800$ divides by $9600$ with an exact integer quotient ($3$), the baud rate error is exactly **$0.00\%$**.

## 8. Code Walkthrough
Implementation in [`src/main.c`](src/main.c):
1. **Peripheral Setup:**
   ```c
   TMOD = 0x21;  /* Timer 1: 8-bit Auto-Reload, Timer 0: 16-bit Timer */
   PCON &= 0x7F; /* SMOD = 0 */
   TH1   = 0xFD; /* 9600 baud reload */
   TL1   = 0xFD;
   SCON  = 0x50; /* Mode 1, REN=1 */
   TR1   = 1;    /* Start baud clock */
   TI    = 1;    /* Prime transmit flag */
   ```
2. **Byte Transmission Function:**
   ```c
   void bsp_uart_putc(char ch) {
       while (!TI); /* Wait until hardware clears SBUF */
       TI = 0;      /* Clear transmit flag */
       SBUF = ch;   /* Write byte to Serial Data Buffer */
   }
   ```
3. **Paced String Transmission:** Timer 0 generates non-blocking 1.0 ms ticks. The superloop verifies $\Delta t \ge 1000\text{ ms}$ before transmitting `"Hello from 8051\r\n"`, preventing terminal buffer overrun.

## 11. Viva Q&A (Technical Assessment)
1. **Q: Why does the 8051 require Timer 1 for UART baud rate generation?**  
   *A:* The 8051 lacks a dedicated internal fractional baud rate generator. In Mode 1 and Mode 3, the serial clock is derived directly from the overflow rate of Timer 1 divided by 16 (or 32 depending on SMOD). Timer 1 is configured in Mode 2 (8-bit auto-reload) so that overflows occur periodically without software intervention.
2. **Q: What is the significance of the `SMOD` bit in register `PCON`?**  
   *A:* `SMOD` (Serial Mode bit) doubles the UART baud rate when set to 1. When `SMOD = 0`, the baud clock is Timer 1 overflow divided by 32. When `SMOD = 1`, the divisor is reduced to 16, doubling the data rate for higher speed transmission.
3. **Q: What does the `TI` (Transmit Interrupt) flag signify?**  
   *A:* `TI` is a hardware flag in `SCON` set by the microcontroller at the beginning of the transmission of the stop bit. It signals to software that the `SBUF` transmit shift register is empty and ready to accept the next character.
4. **Q: What happens if an 8051 program writes to `SBUF` while `TI == 0`?**  
   *A:* Writing to `SBUF` while the transmitter is actively shifting out a previous character causes data corruption. The new byte will overwrite the shift register contents, producing garbled transmission over the wire.

## 12. Troubleshooting
- **Garbage or unreadable characters appear in PuTTY:**
  - Verify that the crystal is 11.0592 MHz and not 12.0 MHz. (A 12 MHz crystal with `0xFD` reload produces an 8.5% baud error, corrupting serial framing).
  - Verify that PuTTY baud rate is set to 9600, 8 data bits, no parity, 1 stop bit.
  - Verify that the common ground between 8051 and the USB adapter is connected.
- **Nothing appears on the terminal:**
  - Ensure cross-wiring is correct: MCU TXD (Pin 11) must connect to Adapter RXD.
  - Verify that `TR1 = 1` and `TI = 1` during initialization.
